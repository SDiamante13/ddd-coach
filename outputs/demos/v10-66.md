## Findings (fresh-eyes pass)

1. **"Ops" is named inconsistently within a reply (3/4 runs).** Runs 2, 3 and 4 label Ops "(day desk)"/"(night shift)" under RB and AMENDED, then plain "Ops" under "booking". That merges the two groups' views into one line. The meaning given ("a customer request once submitted…, and a new booking when the lane or carrier changes") is the day desk's. The prompt says "the same group keeps the same name under every word", but `split labels` and `stable views` both pass, so no check catches a plain team line in a block with no named sibling. Run 1 stayed consistent. Consider a check that a team named by group anywhere must be named in every block.
2. **Uncommitted v11 work fails all four v10 replies.** The working tree's in-progress `question sources` hard check (two short verbatim source quotes after the question) fails runs 1–4. That's expected, since v10 never quotes, but it means `checkReply` on HEAD plus the working tree no longer scores the live prompt. Score production against the deployed commit until v11 ships.
3. **The run 1 caption at 0:50 was wrong for 13 s.** It said the question "opens with which". It opens with "For load 48213". The caption was corrected on video at 1:03, and the AC is unaffected.
4. **Recording viewport is 1280×577, not 578.** It's 1 px off the brief, and the video frame is 578.
5. **Tooling:**
   - `agent-browser find role button --name Retry click` fails with "Unknown subaction: --name". Put the action before the flags: `find role button click --name Retry --exact`. It cost the 76 s cut.
   - `network route <url> --body "<json>"` set in a fresh session after `close` → `set viewport` → `open` did **not** intercept: the request reached production (200, a real reply). That's why run 4 exists and the paid cap was reached. `--abort` in the recording context worked. Check that a `--body` mock actually matched before relying on it.
   - Don't dump the gate's `innerHTML`/`outerHTML` after `fill`. React reflects the controlled input's `value` attribute into the DOM, so the markup contains the password. One dump reached this verifier's tool output during a rehearsal. It isn't in any file, frame or caption.
   - `record stop` again left the session without the cookie. The PNG needed a fresh unlock.
