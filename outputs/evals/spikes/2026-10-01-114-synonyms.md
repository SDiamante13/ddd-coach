# #114 spike: do the repo glossary files alone stop synonyms and abbreviations? (2026-10-01)

Result comment: https://github.com/SDiamante13/ddd-coach/issues/114#issuecomment-5929876752

**Result:** the files alone held the line, so no lint or hook was proposed.
- **Don't use words in new identifiers:** WITH both files 0 / 0 / 0, WITHOUT 5 / 5 / 8.
- **Where the drift came from:** the outside system's spec ("credit memo", `bkg_ref`, `cxl_ts`), not the ticket's shorthand.
- **Only leftover:** a local `inv` block variable, in both arms.

**Cost:** $2.20 for 6 runs (cap $2.50).

## How to reproduce

1. **Toy repo:** create the files below in an empty folder, run `git init` and commit them as the baseline. 6 tests should pass.
2. **Export:** generate `GLOSSARY.md` and `CLAUDE-section.md` from main at `309534e` with the script and fictional coach reply below.
3. **Arms:** make 6 copies of the toy repo, each in a folder with a random name.
   - **W** (3 copies): add `GLOSSARY.md` at the root, and append a blank line plus `CLAUDE-section.md` to `CLAUDE.md`.
   - **N** (3 copies): no change.
4. **Run** this in each copy, with the task text below:
   ```
   claude -p "$(cat task.txt)" --model opus --setting-sources project,local --no-session-persistence \

   ```
5. **Score** `git diff` (with `git add -A -N .` first) plus the final message, by shuffled folder name, using the rubric below.

## Rubric (written before any run)

Scope = NEW Ruby identifiers in lib/ and test/: class, module, method, constant, status value, attr, keyword/positional param, local/block variable, test method name, new file name.
Exempt = string literals and hash keys that docs/ledgerlink.md dictates verbatim ("CreditMemo", memo_no, inv_no, bkg_ref, amt_cents, cxl_ts, doc_type), plus calls to existing baseline names (e.g. calling void_line!).

- **D, Don't use hits (count, distinct identifiers):** identifiers containing `bkg`, `cxl`, `void`, `memo` / `credit_memo` / `CreditMemo`.
- **A, other coined abbreviations / synonyms (count, distinct identifiers):** abbreviations of a domain word not in baseline (`inv`/`invd` for invoice(d), `cn`/`cm` for credit note, `amt`, `ts`, `canc`, `cncl`, `dd` for day desk) or near-synonyms of a glossary term (refund, reversal-as-a-noun, revoke, withdraw, abort). Generic programming names (id, at, doc, payload, json, i, l, x) don't count.
- **Text hits (count):** Don't use words in new comments, test-assertion messages or non-spec strings (e.g. description "Cxl 51210"), reported separately.
- **Boundary (y/n):** spec-dictated LedgerLink keys appear in one mapping place only, with domain names elsewhere.
- **void_line! misuse (y/n):** the run calls the existing `void_line!` (billing-mistake removal) to implement the cancellation or credit note.
- **Completion (0-4):** +1 cancellation recorded with time; +1 invoiced booking gets a credit note; +1 LedgerLink document posted per spec (all 6 keys, negative amount); +1 day desk weekly count. Tests pass (y/n).
- **Holds the line** = D = 0 and A = 0 in a run.

## Caveats
- **Small n:** 3 per arm, one task, one model (`claude-opus-5-5`), one toy repo written by someone who knew the hypothesis.
- **Scoring:** one scorer. The blinding leaked a little, because two W runs mention the glossary in their final message.
- **The task names the words:** each Don't use word is quoted in the export. Drift from long sessions, or from words no thread quoted, isn't tested.

## Domain language (from GLOSSARY.md)

Generated by DDD Coach, 1 Oct 2026, from one coach reply to a pasted thread. Regenerate rather than hand-edit.

Settled terms. Build on these, each in the context named (meanings in `GLOSSARY.md`):
- `booking` for Ops (day desk), Finance, Code; in code `Booking`, `booking.rb`, `submitted_at`, `invoiceable_at`
- `cancellation` for Ops (day desk)
- `credit note` for Finance

- Use these exact terms in specs, tickets, code names, filenames and the API surface. Never abbreviate or rename them; if something has no name, ask instead of coining one.
- A term's meaning depends on its context; never merge meanings across contexts. Build every settled meaning in each context that uses it, giving each context its own result; only Unsettled points wait.

class Booking
  SUBMITTED = "SUBMITTED"
  AMENDED = "AMENDED"
  DISPATCHED = "DISPATCHED"

  attr_reader :id, :ref, :customer, :lane, :carrier, :pickup_at, :rate_cents,
              :status, :submitted_at, :dispatched_at, :invoiceable_at

  def initialize(id:, ref:, customer:, lane:, carrier:, pickup_at:, rate_cents:, submitted_at:)
    @id = id
    @ref = ref
    @customer = customer
    @lane = lane
    @carrier = carrier
    @pickup_at = pickup_at
    @rate_cents = rate_cents
    @submitted_at = submitted_at
    @status = SUBMITTED
  end

  def amend!(pickup_at:)
    @pickup_at = pickup_at
    @status = AMENDED
  end

  def dispatch!(at:)
    @dispatched_at = at
    @status = DISPATCHED
  end

  def mark_invoiceable!(at:)
    @invoiceable_at = at
  end

  def invoiceable?
    !invoiceable_at.nil?
  end

#### `lib/invoice.rb`

```ruby
class Invoice
  Line = Struct.new(:booking_id, :description, :amount_cents, keyword_init: true)

  attr_reader :id, :customer, :lines

  def initialize(id:, customer:)
    @id = id
    @customer = customer
    @lines = []
  end

  def add_line(booking_id:, description:, amount_cents:)
    @lines << Line.new(booking_id: booking_id, description: description, amount_cents: amount_cents)
  end

  # Removes a line billed by mistake (wrong rate or wrong customer) before the invoice is sent.
  def void_line!(booking_id)
    @lines.reject! { |line| line.booking_id == booking_id }
  end

  def total_cents
    lines.sum(&:amount_cents)
  end
end
```

#### `lib/invoicing.rb`

```ruby
require "booking"
require "invoice"

class Invoicing
  def initialize(invoices)
    @invoices = invoices
  end

  def bill(booking, at:)
    invoice = invoice_for(booking.customer)
    invoice.add_line(booking_id: booking.id, description: "#{booking.ref} #{booking.lane}", amount_cents: booking.rate_cents)
    booking.mark_invoiceable!(at: at)
    invoice
  end

  def invoice_for(customer)
    @invoices.all.find { |invoice| invoice.customer == customer } ||
      @invoices.add(Invoice.new(id: "INV-#{@invoices.all.size + 1}", customer: customer))
  end
end
```

#### `lib/week.rb`

```ruby
require "date"

module Week
  def self.covers?(time, today)
    return false if time.nil?

    monday = today - (today.cwday - 1)
    (monday...(monday + 7)).cover?(time.to_date)
  end
end
```
